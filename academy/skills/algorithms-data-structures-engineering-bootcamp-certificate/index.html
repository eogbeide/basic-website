Bootcamp Mastery Certificate B28

Primary academic spine: MIT 6.006 Introduction to Algorithms, reinforced with freeCodeCamp / Jovian's 12.5-hour project-based data structures and algorithms course. Learn to select structures and algorithms by invariant, correctness and complexity - then prove the choice empirically in code.

Benchmark: MIT OpenCourseWare publishes the 6.006 lecture videos freely, and freeCodeCamp publishes the Jovian data-structures-and-algorithms course publicly. Zuyini curates these resources into an independent build-and-proof credential and does not represent an MIT, freeCodeCamp or Jovian-issued certification.

Build-Along Checkpoints

  • Checkpoint 1: Implement dynamic-array, linked-structure or sequence operations and annotate each with asymptotic cost; benchmark at multiple input sizes and compare measured growth to the model.
  • Checkpoint 2: Implement at least two sorting strategies and a hash table; define invariants, collision behavior and test cases, then explain when each structure/algorithm is the stronger choice.
  • Checkpoint 3: Build an ordered set using a tree; implement traversal/search/update behavior and demonstrate how balancing changes worst-case height and operation cost.
  • Checkpoint 4: Implement a binary heap / priority queue and use it in a realistic scheduling or selection problem; validate heap invariants after every mutation.
  • Checkpoint 5: Represent a graph and implement BFS, DFS and Dijkstra; test disconnected, cyclic and weighted edge cases and justify the traversal/shortest-path choice.
  • Checkpoint 6: Solve one nontrivial dynamic-programming problem from recurrence to memoized/tabulated implementation; show subproblem definition, correctness argument and complexity.

7-Day Independent Capstone

  • Day 1: Choose one realistic optimization/search problem plus a benchmark set; define input constraints, correctness oracle, baseline approach and expected
  • Day 2: Implement sequence/set primitives, sorting and hashing with unit/property tests; instrument operation counts or timing across growing inputs.
  • Day 3: Add trees and heaps; enforce structural invariants automatically and compare operation/memory behavior against simpler baselines.
  • Day 4: Model the problem as a graph where appropriate; implement BFS/DFS and a shortest-path method, then test adversarial/disconnected/weighted cases.
  • Day 5: Implement a dynamic-programming solution for one subproblem; derive recurrence, prove subproblem coverage and compare against a naive or greedy
  • Day 6: Run empirical complexity experiments, profile bottlenecks and document where constant factors or memory change the theoretical recommendation.
  • Day 7: Publish repo, correctness/invariant tests, complexity notebook/plots, benchmark data, algorithm-choice memo, demo video and a short design review

Algorithms - Prove, Implement, Benchmark & Defend

Go beyond memorizing interview patterns. Completion requires implementations whose invariants are tested, complexity is derived and measured, graph and dynamic-programming choices are justified, and tradeoffs are defended against realistic constraints and alternative algorithms.

Proof Rubric — What Must Be Shown

  • CORRECTNESS: Invariants, edge cases + reproducible tests
  • COMPLEXITY: Time/space analysis + empirical growth
  • STRUCTURES: Arrays/hash/tree/heap implementations
  • GRAPHS: BFS/DFS/shortest-path evidence
  • DP: Recurrence, subproblems + working solution
  • BENCHMARKS: Measured scaling + interpretation
  • JUDGMENT: Algorithm choice tied to constraints
  • COMMUNICATION: Proof, tradeoffs + design review
