Bootcamp Mastery Certificate B19

Primary spine: Harvard CS50P testing foundations + freeCodeCamp Postman API testing + a full Playwright/TypeScript automation course, reinforced by Microsoft Playwright production practice. Move from unit and API tests through browser automation, accessibility, visual checks and CI/CD quality gates.

Benchmark: Harvard CS50, freeCodeCamp, Microsoft Developer and the referenced Playwright educator publish the linked learning videos publicly. Zuyini curates those resources and applies an independent build-and-proof completion rubric; this is not a provider-issued certification or endorsement.

Build-Along Checkpoints

  • Checkpoint 1: Define a risk-based test strategy for a small web/API product: critical journeys, test layers, environments, data and release gates.
  • Checkpoint 2: Write unit tests for core business logic with deterministic fixtures, edge cases and explicit exception/failure coverage.
  • Checkpoint 3: Build Postman API tests for happy paths, auth, negative cases, schema validation and chained workflows; automate with CLI.
  • Checkpoint 4: Build Playwright browser tests using robust locators, assertions, fixtures and page objects; include at least one accessibility check.
  • Checkpoint 5: Add visual or cross-browser evidence, flaky-test detection and a quarantine/fix policy; measure runtime and failure signal quality.
  • Checkpoint 6: Run the suite in CI on every pull request; publish reports/artifacts, block a known regression and demonstrate root-cause diagnosis.

7-Day Independent Capstone

  • Day 1: Choose a real application/API and create a quality-risk map, release criteria and layered test plan tied to user impact.
  • Day 2: Build unit tests and API happy/negative-path coverage; capture baseline defects and coverage gaps before automation expands.
  • Day 3: Add schema/contract assertions, auth cases and data-driven API workflows; make the API suite runnable from the command line.
  • Day 4: Automate the highest-risk browser journeys with Playwright; add fixtures/page objects plus accessibility and visual checks.
  • Day 5: Harden reliability: remove timing assumptions, detect flakiness, test failures intentionally and document failure taxonomy.
  • Day 6: Integrate unit/API/E2E suites into CI with artifacts, thresholds and one deliberately injected regression that blocks release.
  • Day 7: Publish repo, test strategy, trace/report evidence, defect examples, CI screenshots, demo video and a release-readiness memo.

Software Quality - Test, Automate, Gate & Diagnose

Build a production-quality test system rather than a collection of scripts. Completion must show layered testing, API contracts, robust browser automation, accessibility or visual evidence, CI enforcement, defect diagnosis and a release decision supported by reproducible test artifacts.

Proof Rubric — What Must Be Shown

  • STRATEGY: Risk-based layers + release gates
  • UNIT: Deterministic logic + edge-case tests
  • API: Auth, schemas + negative workflows
  • E2E: Robust Playwright user journeys
  • QUALITY: Accessibility/visual + flaky-test evidence
  • CI/CD: Automated gates + reports/artifacts
  • DEBUGGING: Failure taxonomy + root-cause proof
  • PORTFOLIO: Repo, demo + release-readiness memo
