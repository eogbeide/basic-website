Hands-On Build Lab — Build Sequence

  • 01 – ADK starter: Create a Python/TypeScript ADK agent with clear instructions, session/state handling and one local function tool.
  • 02 – Grounding + memory: Add approved enterprise/public context; define session memory behavior and source/uncertainty handling.
  • 03 – MCP: Connect a Google Cloud remote MCP server or publish/connect your own; authenticate and inspect tool schemas/behavior.
  • 04 – Registry + multi-agent: Register/discover an agent or MCP toolset; compose a parent orchestrator with a specialized remote/sub-agent using ADK/A2A patterns.
  • 05 – Security: Use IAM/service accounts/ADC, least privilege, secrets and gateway/policy controls; test denied and malformed requests.
  • 06 – Evaluate + observe: Create task/trajectory evals; inspect traces, latency, errors, token spend and tool-selection failures.
  • 07 – Deploy: Deploy through the appropriate managed runtime/Cloud Run/GKE path; add autoscaling, monitoring, release/rollback and cost guardrails.

Functional System Capstone

Build a functional GCP agentic system with ADK that uses grounded context, calls a remote or custom MCP toolset, composes at least two specialized agents or one remote A2A agent, authenticates through IAM, passes trajectory/task evaluations, emits operational telemetry and is deployed to a cloud runtime with rollback and runbook evidence.

Proof Rubric

  • Working ADK architecture
  • correct session/state behavior
  • MCP tool discovery
  • registry/A2A composition
  • IAM correctness
  • least privilege
  • useful evals
  • diagnosable traces
  • reliable failure handling
  • deployability
  • latency/token/cost evidence
  • secure secret handling
  • production readiness and a clear architecture decision record
