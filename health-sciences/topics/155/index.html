    ERROR LOG + ANALYTICS-DRIVEN REMEDIATION

    ShareXinf

    ALL YEARS | PAGE 37C - CAPTURE -> TAG -> REPAIR -> RE-TEST -> RECALIBRATE

    An error log is useful only when it changes future behavior. The objective is to reduce repeat errors on new problems; a beautifully organized spreadsheet that does not alter the next study session is documentation, not remediation.

    F. ERROR TAXONOMY - DIAGNOSE THE FAILURE

    Error typeWhat happenedBest repair
    Knowledge / retrievalFact, mechanism, association or formula was absent or unavailable without cues.Targeted reteach -> closed-book retrieval -> new item after delay.
    Reasoning / discriminatorFacts were known but the causal chain, localization or decisive clue was misused.Compare top 2 choices; write the discriminating rule; practice look-alike cases.
    Management sequenceCorrect action chosen at the wrong time or after a missed stabilization/test step.Write the algorithm as NOW -> NEXT -> DEFINITIVE -> DISPOSITION.
    Question-reading / taskLead-in, timeframe, age/setting, negation or key modifier was missed.Underline task + time; summarize what is being asked before options.
    Data / graph / calculationAxes, units, direction, denominator or interpretation failed.Reconstruct the relationship; solve 2-3 fresh representations.
    Image / practicalRecognition depended on one memorized image, angle, slide or specimen.Re-test with new views / modalities; verbalize defining features.
    Timing / attentionSlow processing, rushed final items, careless changes or fixation.Timed micro-sets; establish stop rules; track late-block decline.
    Overthinking / low confidenceMoved away from the best-supported answer without new evidence or guessed correctly.State the decisive evidence before changing an answer; review unstable corrects.

    G. THE 48-HOUR REPAIR LOOP

    StepExecution
    1. CaptureRecord only misses/uncertain corrects with educational value. Save the tested rule, not the entire explanation.
    2. TagChoose one primary error mechanism. If everything is tagged "knowledge," the taxonomy is not being used.
    3. RepairUse the smallest intervention that fixes the cause: one paragraph/video segment, one algorithm, one redraw or one worked example.
    4. RetrieveClose the source and reproduce the repaired rule from memory.
    5. Re-testWithin ~24-72 hours, use a NEW vignette/image/problem. Recognition of the old answer does not count.
    6. Escalate / archiveIf the same error recurs, deepen the repair. If it transfers correctly twice, reduce review frequency.

    H. WEEKLY DASHBOARD - WHAT TO TRACK

    MetricWhy it mattersTrigger for action
    Repeat-error rateBest signal that remediation is failing.Same mechanism misses twice -> targeted re-teach + fresh set.
    Low-confidence correct rateDetects unstable knowledge hidden by % correct.High guessing -> retrieval / discriminator work.
    Time per item + late-block dropSeparates knowledge from endurance/pacing.Accuracy falls in final quartile -> timed stamina practice.
    Domain trendShows decay and blind spots across systems/rotations.Weak domain persists across multiple sets/assessments -> increase weighting.
    Resource-to-output ratioPrevents passive overconsumption.Video/reading time rises while retrieval/questions stagnate -> prune resources.
