Bootcamp Mastery Certificate B31

Primary spine: TechWorld with Nana Kubernetes full course, reinforced with current CNCF bridges for Helm, Argo CD and autoscaling plus a production observability course. Move from manifests and networking to state, GitOps, security, monitoring, scaling and failure recovery.

Benchmark: TechWorld with Nana and the CNCF publish the cited Kubernetes, Helm, Argo CD, security and autoscaling videos publicly; the observability course is also publicly available on YouTube. Zuyini curates these free learning resources and adds an independent build-and-proof rubric; this is not a Kubernetes, CNCF or provider-issued certification.

Build-Along Checkpoints

  • Checkpoint 1: Create a local or managed cluster and deploy a multi-service application using namespaces, Deployments, Services, ConfigMaps, Secrets and resource requests/limits.
  • Checkpoint 2: Expose traffic through Ingress/TLS, add readiness/liveness/startup probes and prove safe rolling updates plus rollback from a deliberately bad release.
  • Checkpoint 3: Add persistent storage and a stateful component; document PVC/StorageClass behavior, backup assumptions and recovery after pod/node disruption.
  • Checkpoint 4: Package the application with Helm and manage environment-specific values without duplicating manifests; show upgrade, rollback and configuration-drift evidence.
  • Checkpoint 5: Implement GitOps with Argo CD; prove desired-vs-live reconciliation, controlled promotion and recovery from an out-of-band manual change.
  • Checkpoint 6: Instrument cluster/app metrics with Prometheus/Grafana, define SLO signals, add autoscaling and security controls, then diagnose an injected resource or networking incident.

7-Day Independent Capstone

  • Day 1: Define application topology, namespaces, trust boundaries, SLOs, capacity assumptions and cluster acceptance tests; provision the target cluster.
  • Day 2: Containerize and deploy stateless services with declarative manifests, probes, resource requests/limits, ConfigMaps/Secrets and repeatable kubectl
  • Day 3: Add Services, Ingress/TLS, NetworkPolicy/RBAC boundaries and one stateful workload with persistent storage and documented recovery expectations.
  • Day 4: Convert deployment to Helm with reusable values and versioned releases; demonstrate upgrade and rollback with a deliberately faulty release.
  • Day 5: Add Argo CD GitOps, pull-based reconciliation and environment promotion; prove drift detection and restoration after an unauthorized manual change.
  • Day 6: Add Prometheus/Grafana dashboards, alerts and autoscaling; inject CPU/resource/network or pod failure and diagnose from cluster and application
  • Day 7: Publish repo, manifests/charts, architecture diagram, GitOps evidence, security notes, SLO dashboard, incident timeline, recovery proof and operations

Kubernetes - Deploy, Reconcile, Observe & Recover

Operate a production-style Kubernetes application rather than stopping at kubectl syntax. Completion requires declarative workloads, ingress and state, Helm packaging, GitOps reconciliation, observability, autoscaling, access/network boundaries and failure-recovery evidence.

Proof Rubric — What Must Be Shown

  • WORKLOADS: Declarative manifests + probes/resources
  • NETWORKING: Services/Ingress/TLS + segmentation evidence
  • STATE: Persistent storage + recovery behavior
  • HELM: Reusable chart + upgrade/rollback proof
  • GITOPS: Argo reconciliation + drift recovery
  • OBSERVABILITY: Prometheus/Grafana + SLO/alert evidence
  • SCALE: Autoscaling behavior + capacity rationale
  • SECURITY: RBAC/policy boundaries + incident recovery
