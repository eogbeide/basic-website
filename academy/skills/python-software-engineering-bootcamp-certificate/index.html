Build-Along Checkpoints

  • Checkpoint 1: Create a small command-line program with functions, arguments, return values, clear naming and conditionals that cover normal and edge-case behavior.
  • Checkpoint 2: Add loops and data structures for a real workflow; refactor repeated logic and document the tradeoff between simplicity and abstraction.
  • Checkpoint 3: Introduce defensive validation and exception handling; create malformed-input cases and prove that failures are handled intentionally rather than hidden.
  • Checkpoint 4: Split functionality into modules and use at least one appropriate standard or third-party library; document what the dependency adds and its limits.
  • Checkpoint 5: Write automated unit tests for core behavior and edge cases; demonstrate a failing test, the fix and regression protection.
  • Checkpoint 6: Add file I/O plus regex or structured parsing, then use classes where they materially improve the model; finish with a clean final-project walkthrough.

7-Day Independent Capstone

  • Day 1: Choose a useful problem, define users, inputs/outputs and acceptance criteria; create repo structure and a minimal working Python baseline.
  • Day 2: Implement core functions, conditionals, loops and data structures; add representative normal, boundary and invalid-input examples.
  • Day 3: Refactor into modules; add exceptions, validation and one library integration; document decisions and known limitations.
  • Day 4: Add file-based persistence or ingestion and regex/structured parsing; create repeatable sample data and failure cases.
  • Day 5: Add classes where useful and write a meaningful unit-test suite; use tests to drive at least one bug fix or refactor.
  • Day 6: Polish CLI/user flow, packaging/run instructions and reproducibility; run the full test suite and complete a code-quality/self-review pass.
  • Day 7: Publish repo, README, architecture/module map, tests, sample data, failure log, demo video and a short engineering memo explaining tradeoffs and next steps.

Python - Design, Test, Refactor & Ship

Build a non-trivial Python application that is correct, maintainable and demonstrably your own. Completion requires modular functions/classes, robust input and exception handling, persistent file data, regex or structured validation, automated tests and a clearly documented final-project rationale.
